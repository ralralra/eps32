# 완성 펌웨어 — 앱 연동 출석체크

앱에서 [출석체크 시작]을 누르면 LED가 깜빡이고, 학생증을 태그하면 앱에 결과가 뜹니다.

## 먼저 필요한 것

- [`uid_test`](../uid_test/) 로 배선·학생증 확인 완료
- [`../../apps_script/README.md`](../../apps_script/README.md) 로 중계서버 배포 완료 (URL 확보)

## 설정

`rfid_attendance.ino` 상단 [설정] 4줄만 수정:

```cpp
const char* WIFI_SSID  = "와이파이이름";       // 2.4GHz 와이파이만 가능!
const char* WIFI_PASS  = "와이파이비밀번호";
const char* RELAY_URL  = "https://script.google.com/macros/s/배포ID/exec";
const char* DEVICE_ID  = "DEV001";            // 앱과 같은 리더기 이름
```

## 동작 확인 (시리얼 모니터 115200)

1. `접속 완료! IP: ...` → 부저 삑삑
2. 앱(또는 브라우저)에서 세션 시작 → 2초 안에 `모드 변경: IDLE → ATTEND` + LED 깜빡
3. 학생증 태그 → `✅ 출석 확인! → OK,김세이프,출석,08:55:01` + 삑삑
4. 앱 결과 화면에 이름·시각·상태 표시

ESP32 없이 앱만 테스트하려면 브라우저에서
`중계서버URL?action=tag&device=DEV001&uid=등록된UID` 를 열면 태그를 흉내낼 수 있습니다.

## LED / 부저 신호 정리

| 신호 | 뜻 |
|---|---|
| LED 꺼짐 | 대기 중 (세션 없음) |
| LED 천천히 깜빡 (0.5초) | 출석 세션 — 학생증을 태그하세요 |
| LED 빠르게 깜빡 (0.15초) | 등록 세션 — 새 학생증을 태그하세요 |
| 삑삑 (짧게 2번) | 성공 (출석 기록됨 / 등록됨) |
| 삐— (길게 1번) | 실패 — 시리얼 모니터에서 사유 확인 (미등록/중복/다른 학생 카드) |

## 자주 걸리는 것

- **와이파이 접속 안 됨**: ESP32는 **2.4GHz만** 지원. 5GHz 전용 SSID는 안 붙습니다.
- **폴링 응답이 이상함**: RELAY_URL이 `/exec`로 끝나는지, 배포 액세스가 "모든 사용자"인지 확인.
- **`HTTP 오류: -11`이 반복됨**: 읽기 시간 초과입니다. 연결은 됐지만 응답이 늦은 것.
  - 최신 펌웨어인지 확인 (타임아웃 25초 + 자동 재시도 적용)
  - 브라우저에서 같은 배포 URL(`?action=periods`)이 정상 응답하는지 확인 —
    브라우저도 느리면 서버(배포) 쪽 문제, 브라우저는 빠른데 ESP32만 느리면 회선 문제
  - 핫스팟은 지연이 큽니다. 가능하면 일반 2.4GHz 와이파이를 쓰세요
  - Apps Script는 첫 요청(콜드 스타트)이 느립니다 — 처음 한두 번 실패 후 정상화되기도 합니다
- **태그해도 반응 없음**: LED가 깜빡이는 상태(세션 중)에서만 태그가 전송됩니다.
