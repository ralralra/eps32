# 0단계 — 배선 확인 + 학생증 UID 테스트

가장 먼저 하는 것. 와이파이도 서버도 필요 없습니다.

## 확인 방법

1. [`../../docs/wiring.md`](../../docs/wiring.md) 대로 배선
2. 라이브러리 매니저에서 **MFRC522** (by GithubCommunity) 설치
3. `uid_test.ino` 업로드 → 시리얼 모니터 **115200**
4. 확인 순서:
   - `✅ 리더기 연결 OK` 가 나오는지 (안 나오면 배선 확인)
   - 학생증을 대면 `카드 인식! UID = A1B2C3D4` 가 찍히는지

## 리더기는 OK(0x92 등)인데 카드 인식이 안 될 때

순서대로 확인하세요:

1. **카드를 안테나 한가운데에 1cm 이내로 밀착**하고 2~3초 유지 (인식 거리가 매우 짧습니다.
   책상에 모듈을 놓고 카드를 위에 얹는 게 확실합니다)
2. **폰에서 NfcA로 확인된 카드**(교통카드 등)를 먼저 태그 → 이게 되면 리더기는 정상이고
   **그 학생증이 Type A가 아닌 것** (아래 3번)
3. **학생증을 폰의 NFC Tools 앱으로 스캔** → "이용가능한 기술"에
   - `NfcA` 있음 → RC522로 읽혀야 정상. 1번(밀착)을 다시 시도
   - `NfcB` / `NfcF`만 있음 → **RC522로는 읽을 수 없는 카드**입니다.
     (Type B 학생증이면 RC522 대신 **PN532 모듈**(Type A/B/FeliCa 지원)로 교체해야 합니다)
4. 아무 카드도 안 되면 → 3.3V 전원이 약한 경우가 많습니다. USB 허브 대신 PC에 직접 연결,
   짧은 케이블 사용, 점퍼선 접촉 확인

> 코드에는 안테나 감도를 최대로 올리는 설정(`PCD_SetAntennaGain(RxGain_max)`)이 이미 들어 있습니다.

## 이 단계에서 판가름 나는 것

- **UID가 찍힌다** → 그 학생증은 이 시스템에서 쓸 수 있습니다. 다음 단계로!
- **리더기는 OK인데 학생증이 인식 안 된다** → 그 카드는 Type A 방식이 아닐 수 있습니다.
  다른 카드(교통카드 등)로 리더기 자체는 정상인지 확인해 보세요.
- **폰 NFC는 매번 UID가 바뀌므로** 이 시스템에는 쓸 수 없습니다 (실물 카드만).
